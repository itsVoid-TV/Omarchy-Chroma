## Installer boundary

`setup` no longer contains a repository URL, remote branch selection or clone
command. It copies its local source, omits `.git` and Python caches, validates
the staged snapshot, checks the plugin ID and activates the same snapshot.
Destination collisions, cancellation, activation recovery and independent Bash
consent are retained. A destination nested inside the source is rejected to
avoid recursively copying the installation staging directory.

`install.sh` resolves the local source beside itself or accepts `--source DIR`.
A detached/incomplete installer fails before changing the installation; inline
execution without an explicit source is rejected even inside a checkout. There
is no Chroma download fallback. The existing pinned ble.sh dependency URL and
SHA-256 verification remain unchanged.

ZIP installation produces an independent snapshot without Git metadata. Its
update procedure is documented; Git-managed widget installations still use
Omarchy's plugin manager. No system package installation or privilege escalation
was added to either shipped installer.

## Input behavior

`CHROMA_ENTER_ACCEPT=1` binds both `C-m` and `RET` in Emacs, Vi insert and Vi
normal keymaps to `accept-line syntax`. Bindings work with deferred keymap
loading and later editing-mode changes. Emacs and Vi insert retain continuation
for incomplete Bash input; Vi normal dispatches through its native accept widget.
`CHROMA_ENTER_ACCEPT=0` leaves upstream/custom bindings untouched in new shells.

Bracketed paste and `accept_line_threshold` are not changed. Pasted newlines do
not submit commands; an explicit Enter accepts the buffer. User overrides of
these options remain visible in Doctor. Ctrl+C discards in Emacs. Native Vi
Ctrl+C behavior is preserved; its documented whole-buffer recovery is Escape,
`H`, `dG`, `i` (ble.sh's plain `gg` navigates history, unlike Vim's buffer motion).

Doctor reports policy, keymap, loaded Enter bindings, paste settings, threshold
and recovery. It avoids querying unloaded keymaps in a subshell: that could
consume ble.sh's deferred-binding file without retaining the parent bindings.
The isolated panel diagnostic does not claim to inspect already open terminals.

## Verification

Local `tests/run.bash` passed with ShellCheck 0.10.0, the pinned ble.sh build
`0.4.0-nightly+63c23e9` (archive SHA-256 verified), and all 22 upstream palettes
read at Omarchy commit `493067741e081c3b09082da6bfd51e99ec24ef00`:

- Configuration validation, including invalid Enter-policy fallback; assertions
  now fail immediately instead of being masked by subsequent commands.
- 52 parser checks and 44 theme checks, plus safe install/update/remove tests.
- 21 bridge tests, 12 local-bootstrap tests and 4 standalone source-selection
  tests. Network-tool traps ensure detached installers do not fetch code.
- 15 terminal-installer tests (the real ttfx case is a CI-only local skip),
  JavaScript model tests and real ble.sh ANSI-render checks in dark/light themes.
- 13 real ble.sh PTY input tests: no execution on bracketed paste, explicit
  Enter in Emacs/Vi insert/Vi normal, Vi mode transition, both opt-outs, custom
  bindings, mode switching, quote continuation, Emacs cancellation, Vi recovery,
  user paste options, live diagnostics and pre-attach diagnostic side effects.
- Bash syntax checks, ShellCheck and `git diff --check`.

GitHub CI additionally installs Qt 6, builds the pinned real ttfx engine, runs
the Qt control-view tests and captures the actual installer and Bash highlighting
in xterm/Xvfb. Those checks are required before promoting this revision to
`main`; see the exact-SHA run in the issue follow-up. Qt/ttfx rendering was not
available in the local test environment. No native Omarchy/Wayland, multi-monitor
or real-device acceptance is claimed.
